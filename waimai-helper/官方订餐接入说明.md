# 美团官方消费者订餐接入

更新：2026-10-15。

## 实现与验证范围

已按官方文档实现签名客户端、消费者 OAuth、查店、读取菜单与规格、订单预览、确认提交和官方收银台跳转。入口为软件导航“官方订餐”。不依赖安卓设备。

当前只有本地模拟响应测试及页面检查，尚无获准应用凭证，因此没有完成真实美团平台联调。界面不会使用示例商家、模拟订单或红包助手令牌冒充真实接入。个人申请是否获批、平台是否接受本机回调及文档接口当前权限，均需美团确认。

本地验证：后端共 112 项测试、前端 19 项检查已通过，包括签名、跨站 OAuth 回调、凭证不回传、不落盘、菜单属性/必选分类/库存、忌口、预算、一次性确认、超时不重试及支付跳转域名检查。独立预览服务中已实际点击检查新入口、空凭证提示和浏览器控制台；未向美团发送真实订单。

## 使用步骤

1. 本人申请消费者订餐网站应用。OAuth 文档要求已审核的网站应用；仅注册开发者和红包助手登录均不等于获得该授权。
2. 在“官方订餐”填写平台分配的应用 ID、OAuth AppSecret 和消费者接口签名密钥 secret_sign。若平台明确两类密钥相同，可填相同值；不要自行假设，也不要把密钥发到聊天里。
3. 平台必须登记页面显示的回调地址，默认是 `http://127.0.0.1:8765/api/ordering/oauth/callback`。若平台不接受本机回调，需要先解决获准的服务端部署；本地实现不能冒充公网回调。
4. 点击“临时配置应用”，再生成官方授权链接，亲自在美团页面完成授权。软件不请求昵称、头像、用户资料或地址簿接口，也不保存 refresh_token。
5. 主动确认本次必要信息转发，填写 GCJ-02 经度、纬度的角度值和关键词，查询真实商家，选择菜品 SKU、属性和份数。
6. 填写本次收货人、手机、完整地址和位置，确认忌口后获取订单预览。预览只报价，不创建订单。
7. 核对平台返回的菜品、规格、数量、收货信息和总价。默认试运行只演练；真实创建订单需在设置中关闭试运行，并明确确认当前预览。
8. 软件会再次预览检查价格和订单内容。如有变化，必须重新预览确认。真实提交只创建订单，不代替本人支付；收银台跳转仅接受官方 HTTPS 地址。

## 隐私与失败处理

- 应用密钥和消费者令牌只保存在本机 Python 服务内存，最长两小时，退出/清除或关闭进程即失效；不会写入配置、普通日志、浏览器本地存储或聊天。
- 位置、收货信息及本次订单只按本人操作发送至 `openapi.waimai.meituan.com`，不读取已有地址簿、联系人、身份证、银行卡或其他用户资料，不发送可选的 risk_param 身份/设备散列。
- 必须承认必要输入会在当前页面和本机请求处理内存中短暂出现；软件不承诺操作系统、浏览器或平台自身永远不留记录。
- 平台返回的订单地址需展示给本人核对，手机号仅显示脱敏值。收货表单和密钥输入在离开页面时清空；本次收货数据不写入订单历史文件。
- 程序使用 TLS 校验、固定接口域名、不跟随接口跳转、不使用环境代理；不读取浏览器 Cookie，不将红包助手令牌挪作外卖令牌。
- OAuth 校验一次性 state、浏览器专用 HttpOnly/Lax Cookie 和有效期，普通请求保持 CSRF 保护。平台令牌不返回给页面。
- 阻止忌口命中、未知 SKU、未选属性、缺少必选分类、库存不足、无效金额、超预算和预览内容不一致。
- 提交前消耗本机一次性确认票据，并串行处理同一会话。提交超时或响应缺少明确状态时，禁止自动重试或继续预览；请先在美团官方 App 核对，避免重复订单。
- 平台要求风控短信验证时停止，不替用户完成验证或假定已下单。当前未实现平台风控短信的自动续交流程。

## 范围限制

本次为用户选择后的确认提单流程，尚未实现无人值守定时自动选餐、消费者优惠券、淘宝闪购业务接口、订单状态轮询、退款/取消及自动支付。原有安卓模式不因这次接入恢复安装或启用。

# 账号登录与隐私说明

更新日期：2026-10-15

## 官方消费者订餐模块

已新增独立的应用配置、消费者 OAuth、查店、菜单、订单预览和确认提交代码，真实平台联调仍未完成，具体范围见 `官方订餐接入说明.md`。

该模块与下文红包助手短信认证分别管理。用户主动配置的应用密钥及 OAuth 令牌最长只在本机服务内存保留两小时；页面不会取得令牌，也不持久保存密钥。软件不请求用户资料或地址簿。订餐所必需的位置、收货人、地址和电话由用户主动填写、确认后，仅发送给美团消费者接口，平台预览的地址与脱敏电话用于本人核对；不写入本地普通日志、配置或订单历史。支付链接保留在本机内存，页面使用本地跳转入口打开官方 HTTPS 收银台。

保留的查店、菜单、收货预览和本次订单数据也只在运行内存中，清除外卖授权或关闭软件后释放；下文“不读取收货地址/订单”的说明限于红包助手认证本身，不能理解为真实订餐无需处理必要收货信息。

- 登录按钮的本地校验结果会持续显示在表单旁；尚未获取验证码时点击验证，会明确提示下一步，不再无说明地禁用按钮。

## 已实现的范围

| 方式 | 目前如何使用 | 本软件是否获得授权 |
| --- | --- | --- |
| 美团手机号 | 在“账号与登录”页主动获取短信并验证，使用美团官方红包助手的短信接口 | 美团返回有效凭证后才显示已授权；仅本次运行 |
| 美团微信快捷登录 | 打开美团官方登录页，选择该页提供的方式 | 未获得本软件的微信授权，不检测网页账号 |
| 淘宝扫码、手机号 | 打开淘宝官方登录页，由本人完成 | 未接入淘宝闪购消费者授权 |
| 支付宝扫码 | 打开支付宝官方登录页，由本人扫码 | 未获得本软件的支付宝授权，不读取余额或支付资料 |
| 官方安全验证二维码 | 美团短信接口明确要求安全验证时，在本机生成官方验证页面的二维码 | 只用于本次短信安全验证，不冒充通用扫码授权 |

没有微信、支付宝开放平台应用时，不能实现这两种账号直接授权给本软件。打开官方网页不会被当作授权成功。淘宝账号网页登录也不等于本软件获得了淘宝闪购下单权限。

## 数据如何流动

美团短信授权：你本人在本机页面输入手机号 → 本机服务经 HTTPS 临时转发给 `peppermall.meituan.com` → 你本人输入短信验证码 → 美团返回授权凭证 → 凭证仅保存在当前进程内存。

- 手机号、短信验证码不写入文件、配置或日志；不会保存在浏览器的本地存储或会话存储。
- 待验证请求只保留带随机密钥的校验摘要，避免保留完整手机号；随机会话标识不包含手机号或硬件信息。
- 页面验证结束后清空验证码；成功授权、离开账号页或离开页面时清空手机号和验证码输入。输入期间内容仅存在当前页面和处理本次请求所必需的临时内存中。
- 凭证不返回给页面，不写入磁盘；两小时后自动清除，也可点击“清除本软件授权”或关闭软件立即清除。
- 不请求昵称、头像、收货地址、联系人、订单、余额或支付资料。即使官方响应额外包含资料，也不保存或转发。
- 不读取、复制或导出浏览器 Cookie；不会从浏览器、微信、支付宝、淘宝或 iPhone 中导入已有凭证。
- 微信、淘宝、支付宝的官方网页在独立页面打开；网页登录状态和官方网页自行保存的 Cookie 由平台及浏览器管理。清除本软件授权不会退出这些官方网页，需在官方页面自行退出。

软件原有的、由你在设置或清单中主动填写的餐品、地址关键词、Bark 配置和运行记录仍按原有功能保存在本机，与账号授权数据分别处理。

## 本机接口保护

- 服务绑定本机地址，拒绝局域网来源及其他主机名。
- 登录提交需要当前浏览器会话的防伪标识，并拒绝跨网站操作和非 JSON 表单。
- 会话 Cookie 设置 HttpOnly、SameSite=Strict，不设置长期有效期；不同浏览器会话不共享软件授权。
- 登录信息不能放进本机接口网址；日志屏蔽手机号、验证码、凭证及敏感异常内容。
- 不增加统计、广告、远程二维码生成、第三方登录中转或 Cookie 提取服务。
- 官方短信请求校验证书，不跟随重定向，不使用环境中的代理配置；安全验证链接只接受美团官方 HTTPS 域名。

## 当前业务限制

本次实现账号入口及美团短信授权，没有获得查店、菜单、领券、下单或支付接口权限。官方登录模式不会执行原有安卓任务，也不会自动提交订单。

如需使用原有自动流程，在设置中选择“安卓设备”，并配置真实可用的安卓设备。你目前只有 iPhone，可以先使用本次提供的登录和官方网页入口；完整自动点餐还需要后续平台业务接入。

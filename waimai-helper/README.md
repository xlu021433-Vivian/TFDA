新定时提交流程尚未在真实账号端到端验证。下面保留早期功能记录，涉及“提交由本人完成”“不支持网页定时”的旧描述以0.3说明为准。账号、地址、Bark密钥与运行数据只保存在本机，不提交GitHub。

## 网页点餐助手（2026-10-16）

默认进入“网页点餐”，提供电脑 Chrome／Edge 扩展下载和安装说明。使用本人已登录的美团网页，无需开发者应用、安卓或模拟器；iPhone 用于本人登录和付款。

扩展读取当前已加载菜单，辅助忌口筛选、按目标份数加购、核对数量并前往官方结算。复杂规格在官方弹窗中由本人选择，最终提交与付款由本人完成。真实网页流程已验证到订单预览，没有创建订单。淘宝闪购尚未验证。详见 `browser-extension/README.md`。

安装包：项目根目录 `神器-网页点餐助手.zip`，也可从本地面板下载。更新扩展源码或 `pork_guard.py` 后运行 `python build_browser_extension.py` 重新打包；不会自动安装或更改浏览器权限。

## 新版账号登录（2026-10-15）

默认进入“官方登录模式”，无需安卓设备：

- 美团手机号短信授权：由你本人输入并确认；信息仅临时转发到美团官方接口。
- 扫码、微信、淘宝和支付宝：提供对应官方网页入口，由平台页面处理登录。本软件不会读取这些页面的 Cookie，也不会把打开网页显示为已连接。
- 当前没有微信、支付宝开放平台应用，淘宝闪购消费者授权接口也尚未接入，因此没有实现这些账号对本软件的直接授权。
- 红包助手短信授权与消费者订餐接口分别管理；官方订餐客户端代码已实现，但真实平台联调尚未完成。消费者领券及无人值守定时点餐不在本次实现范围。
- 授权凭证只存运行内存，设置两小时有效期；可随时清除，关闭软件后消失。手机号、验证码不写入配置、文件或日志，不获取用户资料。

详细说明见 `登录与隐私说明.md`。更新后请关闭旧运行窗口，再重新双击启动。

以下自动抓取、领券、下单说明属于原有“安卓设备模式”，可在设置中切换；它们仍需要安卓设备。

一个在自己电脑上运行的小软件，双击启动后会在浏览器里打开操作面板：

- **推荐**：自动在美团、饿了么/淘宝闪购里按关键词搜索，读出店铺、满减和菜品，过滤疑似含猪肉的菜，按优惠力度排序。
- **安全清单**：在推荐里勾选你确认过的菜，一键加入。以后只从清单里下单。
- **定时**：每天自动 抓推荐 → 领券 → 生成待支付订单 → 推送到 iPhone，你自己付款。
- **账号**：查看两个平台是否已登录。软件**不保存任何账号密码**。

脚本**永远不碰付款**，只把订单停在「待支付」。

## 一、准备（只做一次）

1. **装 Python 3.9+**（安装时勾选 "Add python.exe to PATH"）。不用另装 adb，软件会自动连接模拟器。
2. **装安卓环境**（二选一）
   - 电脑：MuMu 模拟器 12，设置里打开「ADB 调试」，地址 `127.0.0.1:16384`
   - 云手机：选支持 ADB 的，记下 ADB 地址
3. 第一次连接时，软件会自动往模拟器里装一个叫 ATX 的小助手 App，这是正常的，用来读取屏幕和点击。
4. **在模拟器/云手机里装「美团外卖」「饿了么」**，用短信验证码登录，手动点一次外卖把弹窗、权限都处理掉。
5. **iPhone 装 Bark**（App Store 免费），复制 key。
6. **定位和地址**（很重要）：
   - 在两个外卖 App 的「我的地址」里，把公司、家的地址都存好。
   - 在模拟器/云手机的「虚拟定位 / 位置设置」里，把位置设到你常点外卖的地方附近。否则 App 会按默认位置推荐别处的店，平台也可能因为定位和收货地址差太远而触发风控。
   - 在面板「设置 → 收货地址关键词」里填地址中独特的一段（如大厦名）。软件搜索前会切到这个地址，**结算页看不到它就不提交订单**。
   - 晚饭想送回家：在安全清单那一行的「送到」里单独填家的关键词。

## 二、启动软件

- Windows：双击 `启动-Windows.bat`
- Mac：双击 `启动-Mac.command`（第一次若提示无法打开：右键 → 打开）

第一次会自动安装依赖。启动后浏览器自动打开 http://127.0.0.1:8765 。
**黑色窗口不要关**，关掉软件和定时就停了。

## 三、第一次使用顺序

1. **设置**：填设备地址、Bark key，点「发送测试推送」确认 iPhone 收得到。
2. **账号**：点「检查登录状态」。未登录就点「在设备上打开」，在模拟器画面里登录。
3. **推荐**：点「开始抓取」。如果抓不到或卡住，看下面的「校准」。
4. 在推荐结果里**勾选你确认不含猪肉的菜** → 加入安全清单。
5. **总览**：点「立即领券并下单」试跑（默认试运行模式，不会提交订单）。
6. 试跑几次都成功后，在设置里关掉「试运行模式」，开启定时。

## 四、校准（App 改版或第一次卡住时）

`selectors.yaml` 里的按钮文字是按常见界面写的初始版本，你手机上的版本可能不一样：
1. 在模拟器里手动走到卡住的那一页
2. 面板「设置 → 校准按钮 → 读取当前屏幕」，看真实的按钮文字
3. 用记事本打开 `selectors.yaml`，把对应步骤的文字改掉，保存即可（不用重启软件）

卡住时 `data/screenshots/` 里会有截图。

## 防猪肉的几道关

1. **安全清单**（主防线）：下单只从你亲自确认过的菜里选
2. **推荐过滤**：店名或菜名疑似含猪的直接拦下，标出原因
3. **下单前再查一遍清单**
4. **确认页扫描**：购物车里出现可疑文字立即中止并推送

规则是「宁可错杀」：没注明是什么肉的「肉丝、肉末」、没注明馅料的饺子包子馄饨、烤肠、汤底等，一律拦截。
**注意**：规则只能看菜名，看不到猪油、同锅烹饪。对严格忌口的情况，优先选清真店。

## 风险提示

- 自动化操作可能触发平台风控，最坏情况是账号受限。不要把定时频率调太高。
- App 改版后需要重新校准。
- 先实测：同一账号在 iPhone 和模拟器上同时登录会不会互相挤下线。

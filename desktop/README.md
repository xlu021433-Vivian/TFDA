# 神器独立桌面助手 0.6.0

单个 `Shenqi-Desktop.exe`，左侧是中文点餐、定时和通知，右侧是微软 WebView2 内置的美团官方网页。用户无需 Python、BAT、Chrome 扩展或美团开发者权限。登录不会从外部浏览器迁移，需要本人在右侧重新登录并确认地址。Windows 10/11 x64 需安装系统 WebView2 Runtime；本项目下载并固定微软 SDK，不携带或修改浏览器本体。

使用：下载 EXE 放在固定位置，双击；在右侧登录和确认地址，在左侧输入需求或留空随机，勾选单次授权后开始。单次点餐不启用循环定时。定时页默认北京时间工作日11:00、含配送费预算25元，用户授权后才启用。关闭程序会停止定时，电脑需保持开机。iPhone Bark 在通知页输入自己的 key，本机加密保存；桌面快捷方式可在通知页创建。

复用既有菜单、规格、用券、猪肉筛选和订单号识别引擎。只操作官方可见页面，不调用私有外卖 API；免费券膨胀最多一张，必须实际用券且最终金额在预算内，最多一次提交，付款由本人完成。状态未知时保留防重记录。网页登录、验证码、定位许可和付款需要本人处理。

## 0.6.0：L5 用餐便签

参考用户指定的 L5 主页，更新为浅粉与奶白玻璃表面、莓果色操作、便签输入、衬线问候与预算金额。保留原生 HTML 控件、清晰焦点、键盘标签切换、至少44px操作、固定底部授权和单一助手入口。美团可选舒适排版同步色彩，不改变登录、规格和交易页面。

手机入口为 https://l5space.icu/shenqi/ ，仅有效 L5 管理员会话可用。桌面“付款提醒 → L5 手机控制”需阅读授权并启用，每次启动默认关闭。远程不新增网络监听端口，网站与桌面在同一 Windows 用户的 `ShenqiDesktop/RemoteBridge` 交换有期限的选餐/暂停请求；只接受固定字段，不接受命令、脚本、任意网址或文件路径。编号在执行前持久记录，接收不明不重试；暂停会撤销尚未接收的选餐请求。状态仅回传进度和已核对订单，不包含登录、Cookie、地址或Bark密钥。网站权限与请求校验见 [web/README.md](../web/README.md)。

## 0.5.4：独立窗口白屏排查版

针对本人机器独立窗口整片空白、后台却有页面内容的问题，当前版本在本程序范围使用WebView2软件绘制（`--disable-gpu`），作为兼容排查措施；可能增加CPU占用，未修改系统或其他浏览器的设置。窗口最小化时隐藏网页控件，恢复时重新显示并重排控件。顶部提供不依赖网页渲染的原生“恢复显示”按钮，只重绘，不刷新网页、不清理账号或购物车、不发起加购。渲染进程异常时停止当前任务，保留提交防重记录。连接提示改成“美团内容已加载”，不把后台内容加载视作已验证用户屏幕可见。

隔离测试覆盖两次最小化恢复、手动恢复流程、控件可见性和当前文档未被刷新，并继续验证原有点餐流程。WebView页面截图和这些检查仍不能证明本人屏幕的白屏已解决，需在本人窗口确认。微软参考：[WebView2绘制性能与GPU排查](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/performance)。

## 0.5.3：区分网页取消与实际加载失败

修复旧导航被新导航替换后，取消事件覆盖当前页面状态的问题。仅处理当前导航编号的完成结果；拦截官方页拉起外部App时保留已经成功加载的页面。不放行外部协议或站点。主文档HTTP错误按对应导航的状态码判断，证书、断网和真正被取消的当前导航仍明确报错；页面未完成有效加载前不接受引擎心跳及请求。内置浏览器隔离验证覆盖旧导航取消、拦截App链接、真实502保持失败以及回首页恢复。

## 0.5.2：修正真实页面的桌面缩放

真实商家页截图显示，官方手机页面以整个右栏宽度放大rem尺寸，店名、导航、背景图和购物车过大。舒适排版现在把首页和菜单的rem基准封顶到手机设计尺寸（50px，极窄视口随宽度收缩）。页面使用原生布局及控件，取消舒适排版即恢复官方原始缩放；规格弹窗和登录、地址、交易页面不应用该调整。增加实际WebView2计算样式校验，验证50px封顶和取消后120px原始测试缩放的恢复。

## 0.5.1：真实试运行修复与官方页排版

真实试运行曾误入“医药馆”：旧过滤规则只覆盖药房、药店等，且其他官方业务域名没有及时结束任务。新增医药馆等非餐饮过滤、点击前重新核对列表、菜单加购前再次排除非餐饮商家；跳转至不支持的官方业务页面时明确停止当前任务并保留提交防重记录，不再一直显示加购。

右侧增加“舒适排版”开关，本机记忆，取消即可恢复官方原样。仅调整h5首页商家卡和菜单菜品卡的字体、留白、色调和圆角；规格弹窗和交易、登录、地址页面保持原样。指定餐品的主按钮改为“按需求帮我选餐”。39项回归检查通过，WebView2隔离流程确认跳过医药馆、停止不支持的跳转、切回官方原样，并只提交一笔模拟待支付订单。真实账号尚未完成下单验证。

## 0.5.0：流程检查与界面更新

左侧改为单餐工作台：紧凑的连接提示、需求输入、仅填写的快捷示例、可编辑预算和偏好；开始按钮与本次授权固定在底部，主区域独立滚动。执行时显示四步进度；复杂规格提供左侧“核对并继续”，历史失败默认折叠。只保留一套助手，右侧仍为美团官方页面。

修复与检查：

- 暂停信号在等待控件、选择规格和确认加购前再次检查；不会在暂停后重试未知加购。
- 无可用美团红包时关闭列表并继续核对商家券，已实际抵扣的商家券也可满足必须用券条件；无任何实际用券仍停止。
- 复杂规格交给本人：在官方弹窗只加1份、核对要求后，左侧确认数量并继续。未增加数量时保持等待，不重复加购；需要本人处理时发送一次电脑通知及已配置的手机推送。
- 未登录、预算冲突、无效金额和重复点击在入口清楚提示；切换页面撤销本次确认。
- 任务进行时不能解除提交防重记录。先暂停、核对官方订单再解除；暂停保留未知提交记录。
- 重新打开程序时停止上次未完成的任务，不恢复旧加购或提交，保留购物车与订单防重记录。

验证包括34项回归检查与实际WebView2隔离流程；另检查主按钮始终可见、360px窄栏无横向溢出、右侧无重复浮层、旧任务不会恢复。模拟不产生真实订单，真实账号全流程仍未验证。

## 0.4.3 界面整理

只保留左侧一套神器控制区：输入需求、看进度、点餐授权、定时和通知都在左侧。右侧只显示美团官方网页，用于登录、确认地址、选店、规格和核对订单，不再叠加旧网页助手。旧任务失败记录标为“上次任务已暂停”。

## 0.4.2 修复

识别“想吃河粉 25元预算 一份”，也支持“牛肉饭一份，25元以内”等餐品、中文预算和组合名称。输入后立即显示识别结果；不理解、冲突或额外配料要求会明确提示。支持明确的糖度、冰量、杯型要求，仅在官方规格中唯一匹配且确认选中后加购，否则暂停，不按默认口味替代。解析在本地完成，不需要模型密钥；不是任意复杂语言的通用聊天模型。

普通商品的“加入购物车”和多规格入口都已适配，仍需菜品与购物车数量同时增加才算成功，未知结果不自动重试。规格价格块排除划线原价，避免促销商品被误报价格不明。

右侧已在商家菜单时，单次点餐保留当前商家；没有匹配餐品就暂停，不擅自换店。右侧在首页时才随机选店。空购物车检查、真实用券、最终含配送预算、忌口、单次提交和付款边界保持生效。

## 本机构建

从微软官方 NuGet 下载 `Microsoft.Web.WebView2` **1.0.4258.31**，SHA-256 为 `56f7f4b8bf9aee4b8efefbbdd4f67d5f74ebd1b100ed0806da71bf76af481aa9`。默认缓存位置为 `.tool-cache/webview2/microsoft.web.webview2.1.0.4258.31.nupkg`。

```powershell
python desktop/build.py
npm ci
node --test desktop/*.test.cjs
```

构建脚本读取 desktop/engine 中的可维护引擎源码，添加本次单次任务的独立授权，不修改循环定时配置。SDK、页面资产、许可证和文件哈希清单均嵌入 EXE。首次运行在 `%LOCALAPPDATA%/ShenqiDesktop` 保存运行组件、浏览器登录目录和 DPAPI 加密设置；不读外部浏览器账号，不发送到 GitHub。WebView2 页面消息限定来源，官方页不能直接读密钥或写本机文件。证书错误不会绕过，导航只允许美团及大众点评官方 HTTPS 站点。
